# Matching rules

These rules are literal. No network, language model or semantic comparison is used. UTF-8 BOMs are accepted and removed before comparison. Source offsets refer to decoded characters after that BOM, with the original line endings preserved. They are not byte offsets.

| Kind | Extraction and equality |
|---|---|
| Number | ASCII or full-width digits, optional boundary sign, valid comma groups of three, decimal part (including `.5`), exponent spelling and percent suffix. Dotted digit chains such as version `3.2.1` remain one exact item; `3.2` plus `1` cannot match it. Width is folded and grouping commas removed: `１，０００`, `1,000` and `1000` are the same. Whole numeric tokens are compared; `73` is absent in `1730`. Signs, decimal/version spelling, exponent spelling and `%` remain significant. Heading and numbered-list markers are excluded in both texts, including `## 1.`, `## 1、`, `1.`, `2)`, `(3)`, `４、` and `一、`. They neither create items nor match text quantities. Dates, ranges, units, fractions and hexadecimal syntax are not interpreted; their numeric runs are counted. Numbers inside a wholly lost link or code item are covered by that parent and excluded from the number comparison; numbers in kept/fewer parents and quotations still count. Small-number word spellings follow the rules below. |
| Link | Bare HTTP(S), FTP, mailto and tel addresses, and bare ASCII e-mail addresses such as `duty@example.com`; inline Markdown destinations, reference definitions, and resolved reference uses. Bare e-mail and mailto forms are detected as links; their literal forms remain distinct. A reference definition and each use count independently; use locations mark the bracketed source text. Reference labels fold case and whitespace. Scheme and authority host case normalize; credentials stay exact. Terminal slashes in the path are removed. Path case, query, fragment, ports and percent encoding remain exact. Sentence punctuation and unmatched trailing closing parentheses/brackets are outside a bare URL. Han text and Chinese punctuation end bare addresses; literal Han paths need an explicit Markdown destination. No network or URL validity check occurs. Malformed URL literals remain comparable text. |
| Code | Fenced blocks with backticks or tildes, matching-run inline backticks, and consecutive indented lines. The opening fence's indentation is removed from each content line that starts with that same prefix; this makes list-contained commands match un-indented fences while preserving additional code indentation. An indented block loses four leading spaces or one tab per line. Fence markers, language labels and the newline before the closing fence are outside the contents. An unclosed fence runs to EOF with terminal newlines removed. CRLF/CR normalize to LF. All other spacing, case, punctuation and full-width characters stay exact. A whole piece must occur as a whole extracted code piece in the new text. |
| Quoted string | Nonempty contents inside straight single/double quotes, curly single/double quotes, 「」, 『』 and 《》, including multiline contents and strings inside code. Word apostrophes are excluded as openers/closers. Enclosing marks are outside the item. Within contents, full-width ASCII characters, curly quotes/apostrophes and line endings normalize. Terminal full stops and commas (`.`, `,`, `。`, `，`) are ignored, so moving them outside the closing marks keeps the quotation. Interior punctuation, other whitespace and case stay exact. Exact contents may occur without enclosing quotes. Latin word boundaries prevent matches inside longer Latin words; Han boundaries do not restrict an exact phrase within longer Chinese text. Nested quotation syntax is not parsed recursively. |
| Name | Capitalised Latin candidates need evidence: a candidate within a prose sentence, a run of multiple capitalised words outside headings/table headers (its second capital is evidence beyond a sentence opening), or a 2–10-letter all-uppercase acronym. Single words appearing only at sentence/list openings, headings or table headers are not sufficient. Once a key qualifies, its other eligible old mentions count, including headings and sentence openings. Months, units, currency codes, CSV, small-number words, common sentence words and the contractions I'm/I'll are excluded. Dr., Mr., Ms., Mrs. and Prof. are excluded as names and their dots are not sentence boundaries; the following surname can qualify. After/Thanks are excluded from runs such as After Dmitri/Thanks Ana. A single capitalised word immediately after a label colon is excluded; multiword names there still qualify. Accented Latin letters, apostrophes and hyphens are supported; exact spaces/tabs, case and Latin word boundaries remain significant. Width and curly apostrophes normalize. Code and link spans are excluded. Names contained in a quotation reported lost or fewer are covered by that quotation; mentions outside it still count. Chinese text can surround Latin names. This is evidence-based scanning, not entity recognition. |
| Heading, bold term, table cell | The original unique-item extraction and punctuation-stripping, lowercase substring comparison are unchanged. `--min-len` filters these only, with a minimum of two normalized characters. Tables compare the first cell, or the second when the body first column counts consecutively from zero or one. IDs such as `200` and `404` are not row counters. Rows without a trailing pipe are supported. These checks deliberately do not count repeated structural items; their existing presence test is preserved. |

Small-number words: single-word English spellings zero through twenty except `one`, case-insensitive, match their plain digit spelling. Number words above twenty and compound phrases such as `twenty-one` or `one hundred and two` are deliberately ignored. English `one` is always excluded, both as a pronoun and as a quantity. Chinese 零/〇, 二 through 二十, and 两 match digits only before a quantity suffix: 小时, 分钟, 秒钟, 秒, 次, 天, 周, 月, 年, 日, 点, 人, 张, 本, 页, 台, 元, 楼, 个, 包, 位 or 份. Standalone 一 is always excluded, including 一点/一天 and genuine counts such as 一年; compound 十一 still matches 11. Digits 1 still count, so `1 hour` rewritten as `one hour` is reported lost. This is an intentional conservative miss. Ordinals beginning 第, section/list labels, larger numbers, decimal word phrases and unsupported quantity suffixes are excluded. Thus `4 hours`/`four hours` and `４小时`/`四小时` match. Chinese title words such as 十问 are not quantities under this rule.

Excluded name vocabulary: all English months and their usual abbreviations; unit abbreviations B/KB/MB/GB/TB/PB, KiB/MiB/GiB/TiB, ms/s/sec/min/h, Hz/kHz/MHz/GHz, mm/cm/m/km, mg/g/kg, ml/l, mV/V/mA/A, W/kW/MW/kWh, C/F and AM/PM; currency codes CAD/EUR/USD/GBP/CNY/JPY/AUD/CHF/HKD/NZD; CSV; Dr/Mr/Ms/Mrs/Prof; small-number words including one; I'm/I'll; and The, This, These, Those, An, It, We, You, They, He, She, If, When, While, And, Or, But, Each, Every, After, Thanks. Units, currencies, titles and contractions are excluded case-insensitively. The conservative rule deliberately misses a one-word name only at sentence or heading starts and a name that is also a month. It also misses single label values (`Next meeting: Friday`), other excluded words/units, heading-only names, lowercase names, Chinese personal names, one-letter names and decomposed accent spellings. Names are the least certain kind, last in the first line as tentative names. Interior capitalisation and multiword capitalisation can still be ambiguous.

Hard facts are grouped by kind and normalized key. `new_count >= old_count` means kept; `0 < new_count < old_count` means fewer; `new_count == 0` means lost. Summary counts and the report's list/count cards count distinct groups, not mentions. JSON schema version 2 uses the same distinct counts, while each item's `old_count`, `new_count`, `locations` and `missing_count` retain occurrence evidence. `missing_count` is `max(old_count - new_count, 0)`. A fewer group never contributes to kept/lost counts. Every old occurrence is marked because assigning the loss to one particular location would invent evidence.

Kinds can overlap: a quotation with a number contributes to both counts. A number inside code/link counts separately unless that parent is wholly lost. A name inside a lost/fewer quotation is excluded from the name inventory to avoid reporting the same loss twice; names inside kept quotations can still count. Do not add categories as if they were distinct facts. Moving a literal item is allowed; its meaning, surrounding unit, section, grammatical role or attachment to another fact is not checked. Headings and table cells use the older, looser matching rule, so consult the hard-fact checks as well.

This is a lightweight text/Markdown scanner. Raw HTML links/code, arbitrary programming languages outside Markdown code markers, escaped Markdown constructs and complete nested Markdown syntax are not parsed. A result concerns the extracted literal items, not every possible fact in a document.
